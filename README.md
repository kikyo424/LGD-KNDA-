# OLED FIELDNOTE

웨어러블 OLED 기술 동향을 로컬에서 수집·검색하는 MVP입니다. Python 3.10+와 Node.js 22.12+ 권장. 배포나 유료 계정이 필요하지 않습니다.

## 실행

저장소 루트에서 실행합니다.

```bash
npm ci
# 실제 수집이 불가능해도 데모로 화면 확인 가능
npm run demo
npm run dev
```

브라우저에서 터미널에 표시된 개발 서버 주소(기본 http://localhost:4321)를 엽니다. Windows에서 `python3` 명령이 없으면 `python -m collector.collect` 및 `python -m unittest discover -s tests -v`로 실행하세요. 수집기는 Python 표준 라이브러리만 사용하므로 가상환경이나 pip 설치는 필수가 아닙니다.

```bash
npm run check
npm run build
npm run preview
```

`check`는 수집기 테스트를 실행합니다. 웹사이트 컴파일 검증은 `build`로 수행합니다. 개발 서버를 실행한 상태에서 재수집하면 데이터 파일 변경이 반영됩니다. 운영용 미리보기는 재수집 후 다시 빌드하세요.

## 실제 자료 수집

```bash
npm run collect
```

`npm run demo`는 합성 예시 3건으로 웹 공개용 JSON을 교체하며 DB는 변경하지 않습니다. 화면에 데모 경고가 표시됩니다. 실제 수집 명령은 JSON을 DB 자료로 다시 교체합니다. 네트워크 실패 시에도 데모가 실제 자료로 둔갑하지 않도록 기존 연구 DB만 내보냅니다.

## 현재 범위

- Crossref 공개 API의 네 가지 검색 주제: 웨어러블, 밝기·효율, 전력·구동, 수명.
- 제목에 OLED 또는 organic light / organic electrolumines가 있는 자료만 유지합니다.
- SQLite DOI 중복 제거, 최대 3회 재시도, 30초 타임아웃, 주제 간 1초 대기.
- 부분 실패 시 다른 주제 수집을 계속하며 기존 자료를 보존합니다. 전체 실패는 종료 코드 1입니다.
- 검색, 기술 태그 필터, 발표일 정렬, 원문 링크, 펼침형 검토 정보, 모바일 레이아웃.
- 기업 뉴스, 제품 비교, AI 요약, 특허, 상용화 타임라인은 아직 구현하지 않았습니다.

Crossref는 논문 메타데이터를 제공하며 원문 수집이나 논문 품질 판정을 하지 않습니다. 자동 분류는 제목 기반입니다. 검색 결과에 디스플레이 이외 OLED 연구가 포함될 수 있습니다. 날짜는 제공된 정밀도를 보존합니다. 밝기·전력 수치와 측정 조건을 추측해서 표시하지 않습니다.

## 데이터와 네트워크

`local-data/articles.sqlite`: 로컬 DB(버전 관리 제외).
`src/data/articles.json`: 웹사이트용 공개 메타데이터. 초기 파일은 비어 있습니다.

수집에는 HTTPS `api.crossref.org` 접근이 필요하고, 원문 링크는 `doi.org`로 연결됩니다. 클라우드에서 403 Tunnel 오류가 나면 환경 설정에서 API 도메인을 허용해야 합니다. 일반 PC에서도 방화벽/프록시 정책을 확인하세요. 오류를 피하려고 TLS 검증을 끄지 마세요.

```bash
python3 -m collector.collect --rows 20
python3 -m collector.collect --db local-data/test.sqlite --output local-data/test.json
```

`--rows`는 주제당 1~100개 후보이며 기본 30개입니다. 검색 후보 중 OLED 관련 제목만 채택됩니다. 동일 자료 재수집은 신규 건수 0이 정상입니다. 현재는 기존 자료를 자동 갱신하지 않고 첫 수집 메타데이터를 보존합니다.

## 수동 확인

1. 수집 후 목록과 수집 상태를 확인합니다.
2. 제목 일부를 검색하고 태그별 필터를 선택합니다.
3. 검색 결과가 없는 입력에서 안내가 표시되는지 확인합니다.
4. 정렬 방향을 바꾸고 발표일을 확인합니다.
5. 검토 정보를 펼치고 DOI 원문 링크를 확인합니다.
6. 모바일 너비에서 카드와 필터를 확인합니다.
7. 두 번 수집 후 DB 전체 건수와 신규 건수를 비교합니다.

빈 데이터에서도 사이트는 실행됩니다. 실제 수집에 성공하지 않은 상태는 동향 분석 검증 완료가 아닙니다.
